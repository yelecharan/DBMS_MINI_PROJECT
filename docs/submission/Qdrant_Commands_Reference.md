# Qdrant Commands Reference

The backend service targets collection `incident_embeddings`, 384-dimensional normalized vectors and COSINE distance. Vectors are generated by the genuine `sentence-transformers/all-MiniLM-L6-v2` model on CPU. The model dimension is checked at startup; model/encoding failures surface explicitly and never produce substitute hash vectors. Service methods are in `backend/app/services/vector_service.py`; the HTTP endpoint is in `backend/app/api/routes/vector.py`.

Example HTTP operations (API authorization applies):

```http
POST /api/vector/search
Content-Type: application/json
Authorization: Bearer <access-token>

{"query":"multiple people entered using one employee badge","limit":5,"severity":"HIGH"}
```

The model-backed integration test verified 384-dimensional output, normalization, upsert/retrieval, metadata update and filtered natural-language search against Qdrant 1.14.1. A separate restart check confirmed that a real embedding persisted on disk. The compatible client range is constrained in `backend/requirements.txt`.

Relational incident changes enqueue snapshot events in the same PostgreSQL transaction. The outbox worker retries transient Qdrant failures with backoff, recovers expired leases, and uses idempotent point upserts. An unavailable embedding model is marked as a permanent, visible failure; administrators can inspect and retry failed events after restoring the model.
